# Qivvera

Independent Change Assurance.

**Change → Obligations → Evidence → Gaps → Scope-bound Disposition**

## Registry increment 0.1.0

The first local product interface supports real application registration, change creation, candidate-obligation editing, saved activity and record retrieval. It is backed by a local SQLite database and a session-protected Node API. No demonstration data is preloaded.

This is not yet a hosted product or an independent-verification engine. Every new change remains NOT ASSESSED and has no disposition. Every proposed obligation remains CANDIDATE. References are declared, not verified.

## Verify

Use Node 22 and the locked TypeScript compiler:

```sh
npm ci --ignore-scripts
node scripts/selfcheck.mjs
npm run check
```

The suite contains 90 tests. See `docs/registry-release.md` for actual results and limitations.

## Local registry

Set `OWNER_EMAIL`, `OWNER_PASSWORD_HASH` (a scrypt hash generated by `server/auth.mjs`), and optionally `DATABASE_PATH`, `PORT`, and `PUBLIC_ORIGIN` in your development environment. Keep secrets out of source control. The password-hashing function requires a password of at least 16 characters. No default login exists.

```sh
npm run start:registry
```

The local server defaults to `127.0.0.1:3000` and refuses production/public binding. The founder is not expected to perform setup; this is a developer handoff. The next deployment checkpoint will establish protected hosting and managed PostgreSQL after cost approval.

`npm start` retains the original process-health-only foundation endpoint. It is not the registry entrypoint.

## Boundaries

- A change has no readiness result until an assessment occurs.
- Candidate authority cannot be promoted by a client request.
- Wrong-target or missing evidence cannot support READY in the provisional kernel.
- The registry API does not expose that kernel or accept evidence-admissibility flags.
- SQLite is local review storage, not immutable evidence storage or the production database.
- The owner session model is not enterprise IAM.
- No automatic GitHub code ingestion, verifier execution, policy approval or release enforcement is implemented.
